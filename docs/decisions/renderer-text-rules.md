# 렌더러가 지문 문자열을 바꾸는 규칙 — 경위

`docs/harness/ui-render.md`의 줄바꿈 규칙 원문이다.

- **줄바꿈 규칙도 같다 — `parser.breaks.test.ts`가 렌더러가 넣은 모든 줄바꿈을 전수로 본다.** `splitStructuralMarkers`·`splitKnownSectionHeadings`가 문맥 없이 끊으면 문장 한가운데서 줄이 바뀌거나("당신의 팀은 / 3점 추정 기법을…") 문장 끝 숫자가 굵은 목록 번호가 되고("…91, 100. 테스트…") 머리말의 일부만 맞아 접속사가 고아 줄로 남았다("그리고 / 다음과 같은 완화 활동이 있다."). 실데이터 10여 문항이 그렇게 깨져 보였고 어떤 게이트에도 걸리지 않았다(PDF 대조는 공백과 줄바꿈을 지운다). 검사는 `proseLines`(렌더러가 쓰는 바로 그 함수)로 지문·해설 문단을 돌려, 줄머리가 구조 표지(보기·번호·글머리표·"키: 값")가 아니고 앞 줄이 문장·항목을 끝낸 것도 아니면 실패한다. 새 규칙은 **앞 글이 문장·항목을 끝낸 자리인지**(`endsProseUnit`)를 보고, 머리말처럼 서로 포함하는 목록은 긴 것부터 한 번에 맞춘다(`SECTION_HEADING_RE`). 데이터에 `…한` / `다.`로 갈라진 조각이 83곳 있지만 렌더러(`mergeTextContinuations`)가 이어 붙여 화면에는 남지 않는다 — 데이터를 고치려 들기 전에 그 사실부터 확인한다.
