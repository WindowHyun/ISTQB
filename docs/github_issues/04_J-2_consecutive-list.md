## 버그 개요

문제 본문(stem)에 번호 목록(numbered list) 블록이 2개 연속으로 있는 문항에서, 두 번째 목록이 첫 번째 목록의 마지막 항목에 잘못 붙어 하나의 목록으로 병합됩니다.

- 등급: **High**
- 대상 파일: `www/script.js`, `www/data/**`

---

## 재현 절차

1. stem에 두 개의 독립된 번호 목록이 나란히 있는 문항을 연다.
2. 두 목록 사이 구분이 사라지고 한 목록으로 합쳐져 렌더링되는지 확인한다.

## 현재 동작 (버그)

- 데이터에 `type: "matching"` 문항은 **존재하지 않음**. (기존 리포트의 "짝짓기 문항" 설명은 부정확)
- 실제로는 stem에 list 블록이 2개 이상 연속하는 문항이 약 9개 존재함.
- `buildRichBlocks()`의 `pendingList` 누적 로직에서, 두 목록 사이에 비목록 텍스트가 없으면 `flushList()`가 호출되지 않아 연속된 목록 항목들이 하나의 목록으로 합쳐질 수 있음.

> 참고: 기존 리포트에는 "짝짓기(matching) 문항"으로 기술되어 있으나, 실제 데이터에는 matching 타입이 없으며 근본 원인은 **연속 list 블록의 flush 누락**입니다.

## 기대 동작

1. 독립된 두 목록이 각각 별도 목록으로 렌더링된다.
2. 두 목록 사이 구분(빈 줄/블록 경계)이 유지된다.
