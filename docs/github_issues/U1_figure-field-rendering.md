## 개요 (UI/표시 — 수정 보류, 논의용)

> ⚠️ 이 이슈는 **데이터 표시 방식(렌더링)** 에 관한 것으로, 코드/데이터 수정 전에 표시 정책 합의가 필요해 별도로 분리합니다.

표/그림이 포함된 여러 문항에서, 그림 또는 표가 **stem 내부에 image 블록으로 임베드**되어 있으나 최상위 `figure` 필드는 `null`입니다. 반면 다른 그림 문항들은 `figure`에 경로가 설정되어 있어 **처리 방식이 일관되지 않습니다.** 표시 자체는 동작할 수 있으나, 렌더링 규약(어디에 그림을 두는가)이 통일되지 않아 향후 React 마이그레이션·유지보수에 혼란을 줍니다.

## 관찰된 사례

| 세트 | 문제 | 상태 |
|------|------|------|
| ISTQB-B | 22 | 결정 테이블이 `stem` image(`source-visuals/B22-artery-table.png`)로 들어가나 `figure: null` |
| ISTQB-B | 31 | 프로젝트 데이터 표가 `stem` image로 들어가나 `figure: null` |
| ISTQB-B | 32 | 테스트 우선순위 표가 `stem` **평문 텍스트**로 병합됨(표 구조 손실), `figure: null` |
| CSTS-2402FL | 27 | 보기 도식 4개가 `stem` image이나 `figure: null` (다른 그림 문항은 figure 채워짐) |
| CSTS-2018 | 11 | 제어 흐름도가 `stem` image이나 `figure: null` |

> 참고: CSTS-2405 Q30처럼 stem에 image를 임베드하고 보기를 "그림 1~4"로 처리한 케이스는 의도된 정상 패턴으로 보임. 즉 **무엇을 정상 규약으로 삼을지** 정하는 것이 핵심.

## 논의 필요 사항

1. 그림/표의 표준 위치를 `figure` 필드로 통일할지, `stem` 내 image 블록으로 통일할지 결정
2. 표를 이미지로 둘지(B22/B31) vs 구조화 텍스트로 둘지(B32) 정책
3. 결정된 규약에 맞춰 위 문항들을 일괄 정리
