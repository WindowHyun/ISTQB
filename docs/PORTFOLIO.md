## 0. 한 줄 소개 (Hero)
> **ISTQB FL v4.0 / CSTS 한국어 기출 626문항을 풀 수 있는 오프라인 CBT 웹·APK 앱.**
> PDF 원본에서 문제 데이터를 추출·정제하고, 바닐라 JS → React 19로 마이그레이션하며,
> CI/CD·자동화 테스트(유닛 37 + E2E 70)로 품질을 관리한 풀사이클 개인 프로젝트.

- 라이브: `https://<배포도메인>` · 저장소: `github.com/WindowHyun/ISTQB`
- 기간 / 역할: 1인 개발(기획·데이터·프론트엔드·DevOps·QA)

## 1. 문제 정의 & 목표 (Why)
- **문제**: ISTQB/CSTS 기출이 PDF로만 흩어져 있어 반복 학습·오답 관리가 불편.
- **목표**: ① 오프라인에서 CBT처럼 풀 수 있는 앱, ② 그림/표 포함 문제의 정확한 렌더,
  ③ 웹·Android(APK) 동시 지원, ④ 신뢰할 수 있는 데이터 정합성.
- **타깃 사용자**: 자격증 수험생(태블릿/모바일/PC).

## 2. 핵심 기능 (What)
- 4가지 풀이 모드: **연습(즉시 피드백) · 시험(채점) · 랜덤 · 오답 다시풀기**
- 문항 유형: 객관식(단/복수) · 진위형(O/X) · 단답형(텍스트 입력)
- 채점·점수·**오답노트**, 진행률·타이머, 문제 번호 팔레트 네비게이션
- 기록 **내보내기/가져오기**(백업), 글자 크기·새로고침 상태 복원(영속성)
- 그림/표/코드/목록 리치 렌더, PWA 오프라인, 반응형(모바일·태블릿·PC)

## 3. 기술 스택 (How — Stack)
| 영역 | 기술 |
|------|------|
| 프론트엔드 | React 19, TypeScript, Zustand, Vite 7, vite-plugin-pwa |
| 레거시/패키징 | 바닐라 JS(SPA), Capacitor(Android APK) |
| 데이터 | PDF 추출 파이프라인(Python·pymupdf), 세트별 JSON 스키마 |
| 테스트 | Vitest(유닛·jsdom), Playwright(E2E) |
| CI/CD | GitHub Actions(lint·verify·unit·build·e2e), Vercel 자동배포 |

## 4. 아키텍처 (Architecture)
- **단일 데이터 정본**: `www/` → `sync-assets`로 `public/`·`dist/`·root 동기화.
- **이중 런타임**: 웹 운영 = React(dist) / APK·로컬·레거시 E2E = 바닐라 JS(www).
- **데이터 흐름**: PDF → 추출 스크립트 → `data/index.json` + 세트별 `{meta, questions[]}` → `useQuestions` → zustand → 렌더.
- *(추가 준비: 아키텍처 다이어그램 1장 — 데이터·빌드·배포 경로)*

## 5. 엔지니어링 하이라이트 (어필 포인트)
> "기능 구현"보다 **문제 해결 과정**이 강점. 각 항목을 1~3줄 + 근거(커밋/PR)로.

1. **레거시 → React 마이그레이션**(APK는 유지하며 웹만 React로 전환): 데이터 스키마 정합,
   ErrorBoundary, 상태/저장 단일화, 기능 패리티 확보.
2. **배포 전환 트러블슈팅**: Vercel `framework: vite` 미지정으로 "No entrypoint" 빌드 실패 →
   해결. 레거시 PWA 서비스워커 잔존 → **자가 해제 tombstone**으로 캐시 마이그레이션.
3. **데이터 품질 파이프라인**: PDF 추출 아티팩트(문장 조각화 "~다." / 괄호 분할 "(QA)" /
   마크다운 표 raw 노출 / 이미지 과캡처)를 **렌더 보정 + 타게팅 데이터 정리**로 해결.
4. **이미지 재추출**: 오크롭된 figure를 `pymupdf`로 원본 PDF에서 다이어그램 영역만 재추출,
   컨택트시트로 전수 육안 검수(50건).
5. **테스트 전략**: 유닛(파서·정답판정·저장) + **Playwright E2E 70개**(모드·채점·유형·네비·
   설정·영속성·엣지·반응형·접근성) + 전 문항 626 렌더 스윕. 브라우저 차단 환경에선 CI를
   검증 계층으로 활용.
6. **CI/CD**: 5-job GitHub Actions(동시성·캐시·최소권한), main 푸시 시 Vercel 자동배포.

## 6. 도전 & 해결 (Case Studies — 2~3개만 깊게)
> 면접/발표용. STAR(상황-과제-행동-결과)로.
- **CS1. 줄바꿈/렌더 회귀가 반복된 이유**: PDF 데이터가 조각나 있고, 특정 패턴만 막다
  새 패턴이 노출 → **클래스 단위 규칙 + 파싱 전 병합 + enum 가드**로 근본 차단(회귀 테스트 추가).
- **CS2. 이미지 과캡처 전수 점검**: Playwright + PDF 뷰어로 626문항/50 figure 대조 →
  오크롭 식별·재추출, 결과를 회귀 스펙으로 고정.
- **CS3. 데이터·정답 불변 원칙**: 표시 문제를 고치되 문제 내용/정답은 보존, CI `verify`로 보장.
