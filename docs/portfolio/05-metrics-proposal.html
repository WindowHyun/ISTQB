Metrics Proposal

지표 제안서 — 수집 없이 학습 효과를 어떻게 재는가

이 앱에는 사용 데이터 수집이 없습니다. 그래서 "어떤 지표를 볼까"보다 "수집 없이 무엇을, 어떻게 볼 수 있나"를 먼저 정했습니다.

제안 · 미구현목표치 없음 — 베이스라인 측정 뒤 설정
숫자를 쓰지 않은 이유사용자 데이터가 한 번도 수집된 적이 없어서 현재값도, 목표도 근거가 없습니다. 근거 없는 "전환율 30%" 같은 숫자는 넣지 않았습니다. 대신 정의, 데이터 출처, 지금 측정 가능한지, 해석할 때의 주의를 적었습니다.

1. 지금 있는 지표와 없는 지표

있는 것 — 품질 지표

CI에서 나오는 값입니다: 테스트 통과, 뮤테이션 점수, 커버리지, 번들 크기, PDF 대조 일치. 제품이 올바르게 만들어졌는지를 재지만 쓸모가 있는지는 말해 주지 않습니다.

없는 것 — 사용·효과 지표

누가, 얼마나, 어떤 기능을 쓰는지, 그리고 학습이 나아졌는지. 앱 소스에 분석·텔레메트리 코드가 없고(src, package.json 점검), 서버와 계정도 없습니다.

2. 원칙

  • 무수집을 깨지 않는다. 서버·계정이 없다는 점이 이 제품의 구조이자 장점(오프라인, 저작권, 개인정보)입니다. 지표 때문에 이 구조를 바꾸지 않습니다.
  • 측정은 기기 안, 또는 사용자가 직접 내보낸 것에서.
  • 효과 지표를 앞에 둔다. 이 앱의 목적은 "많이 쓰게 하기"가 아니라 "약점이 나아지게 하기"입니다. 체류 시간 같은 지표는 쓰지 않습니다.

3. 북극성 지표와 보조 지표

북극성 — 약점 개선율

정의: 약점으로 지목된 챕터(합격선 미만, 표본 5문항 이상) 중, 이후 재측정에서 정답률이 직전보다 오른 챕터의 비율.

데이터 출처
이력의 createdAt, chapterStats, chapterQuestions — 이미 저장됨(IndexedDB)
측정 가능?
지금 가능 기기 안에서 계산할 수 있고, 새 데이터가 필요 없다
해석 주의
① 재측정을 하지 않은 사용자는 분모에 들어오지 않는다(선택 편향) ② 문항이 겹치는 재측정은 "외워서" 오를 수 있다 ③ 합격선 기준이 맞는지 자체가 가설이다(PRD §9)

4. 수집 방식 비교

방식내용장점단점·위험판단
A. 기기 안 계산북극성·M1·M2를 "내 통계" 화면에서 본인에게 보여 준다(제품팀은 못 봄)무수집 유지. 학습자에게도 가치가 있다(성장 이력)제품 판단용 집계는 못 한다채택
D. 정성 수집제보 시트(이미 있음) + 테스터 인터뷰비용이 낮고 "왜"를 얻는다표본이 작고 응답 편향채택
B. 자발 내보내기 수집테스터가 앱의 백업 JSON(이미 있는 기능)을 동의 하에 제출무서버. 실제 이력으로 북극성을 계산할 수 있다수동·소규모. 답안과 문항 id가 들어 있어 비식별 처리와 동의 절차가 필요하다선택(소규모 테스트 때)
C. 익명 이벤트 서버 수집사용 이벤트를 서버로 전송제품 집계가 쉽다서버·동의·오프라인 큐가 필요하고 무수집 구조와 충돌한다. 규모에 비해 과하다제외

5. 검증이 필요한 가설

가설어떻게 확인판단 규칙(숫자는 베이스라인 뒤)
H1. 약점 = 합격선 미만이 사용자의 직관과 맞다테스터 인터뷰 + M5"내 약점은 여기가 아닌데"라는 반응이 반복되면 상대 순위 방식(제안서의 D안)을 검토한다
H2. 사용자는 오답 복습 시점을 놓친다사례 2의 A안 배포 뒤 정렬 옵션 사용 여부, 인터뷰쓰이지 않으면 B안으로 가지 않는다
H3. 미니 시험 10문항이 재측정에 적당하다M1·M2 + 인터뷰("너무 길다/짧다")M2가 낮고 이유가 길이라면 문항 수를 조정하고, 이유가 다르면 문항 수는 건드리지 않는다
H4. 퀵의 서답형 30% 상한이 적절하다인터뷰, 제보제보에 서답형 편중 불만이 없으면 유지한다

6. 필요한 데이터 변경 (제안)

필드목적지표주의
문항별 마지막 오답·복습 시각경과일 표시, 복습 간격 판단M3백업 스키마·정제 allowlist·왕복 동등성 테스트에 같이 추가한다(필드 유실 사고가 두 번 있었음)
미니 시험·연습의 진입 출처약점 화면에서 왔는지M1, M4연습은 기록하지 않는 정책(D4)과 충돌하므로 "회차가 아닌 카운터"로만 두거나 포기한다
결론당장 할 일은 새로 수집하는 것이 아니라 이미 저장된 이력으로 북극성·M1·M2를 기기 안에서 계산해 보이게 하는 것입니다. 그 결과가 학습자에게 가치가 있는지(내 성장 이력의 연장)를 보고, 새 필드 추가는 그다음에 결정합니다.
