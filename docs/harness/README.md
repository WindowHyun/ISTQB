# 하네스

하네스는 변경이 동작한다는 것을 반복해서 증명하고, 같은 유형의 결함이 다시 들어오지 않게 막는 검사 체계다. 어느 문서를 읽을지는 [`../../AGENTS.md`](../../AGENTS.md)의 경로 표가 정한다.

| 문서 | 영역 |
| --- | --- |
| [`data.md`](./data.md) | 문항 데이터·정답·보정 도구 |
| [`ui-render.md`](./ui-render.md) | 렌더링·레이아웃·렌더러의 문자열 변형 |
| [`app-logic.md`](./app-logic.md) | 풀이 모드·채점·통계·저장 — 반복된 결함 클래스 12개 |
| [`android.md`](./android.md) | 패키징·서명·JS 브리지 계약 |
| [`testing.md`](./testing.md) | 테스트 계층·E2E 규칙·예산 부등식·뮤테이션 게이트 |

릴리스 전 점검은 [`../release-playbook.md`](../release-playbook.md) §0, 결정 경위는 [`../decisions/`](../decisions/).

## 문서를 고칠 때

- 규칙은 한 줄, 근거는 한 줄. 경위와 실측이 필요하면 `docs/decisions/`에 쓰고 링크한다.
- 같은 규칙을 두 문서에 쓰지 않는다. 한 곳에 쓰고 나머지는 링크한다.
- 실측값(테스트 개수·점수·소요 시간)은 적지 않는다. 설정·계약 테스트가 강제하는 값만 적는다.
- 사람이 판단하는 것보다 코드가 강제하는 것이 낫다. 문서로 반복해서 경고하게 되는 규칙은 검사나 스크립트로 옮길 수 있는지 먼저 본다.
