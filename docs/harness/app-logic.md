# 앱 로직 하네스

적용: `src/store/**`, `src/hooks/**`, `src/utils/**`(parser 제외) — 풀이 모드(연습·시험·퀵·오답, 통계에서만 들어가는 챕터 미니 시험 = 내부 모드 `random`), 채점, 챕터 통계·약점 분석, 오답 노트, 저장(localStorage·IndexedDB)·복원, 가져오기/내보내기, 제품(ISTQB↔CSTS) 스코프, 탭 간 동기화.

## 필수 점검

```bash
npm run typecheck && npm run typecheck:test
npm test
npm run test:e2e
```

- 채점·통계 순수 로직 → `npm run test:mutation`. `storage.ts`·`useQuizStore.ts` → `npm run test:mutation:storage`.
- 저장·복원·오프라인 → `npm run test:nf`.
- 회귀 가능성이 있는 동작은 유닛(가능하면 순수 모듈로 꺼내서)이나 E2E 시나리오로 고정한다.

## 퀵 모드

퀵은 다른 모드의 전제를 깬다: 세트가 없어 `setId`가 센티넬(`QUICK`)이고, 회차를 이력(IndexedDB)이 아니라 UI 상태 키(localStorage)에 24시간만 둔다. "세트가 있다 / 이력에 남는다"를 가정한 코드가 조용히 어긋나므로, 퀵을 건드리면 아래 매트릭스의 퀵 행을 함께 확인한다.

## 시나리오 매트릭스

| 영역 | 확인할 것 |
| --- | --- |
| 연습 | 답 선택 즉시 피드백·해설, 다음 문항으로 새지 않음 |
| 시험 | 시작 게이트 → 응시 중 잠금 → 채점 후 결과·잠금 해제, 제한시간 |
| 챕터 미니 시험 | 통계에서만 진입, 무작위 순서에서도 정답 매핑 유지, '연습으로 전체 보기'는 연습 모드로 |
| 오답 | 명시적으로 다시 풀기 전까지 오답 기록 보존 |
| 이동 | 이전/다음 뒤에도 선택·상태 일관 |
| 저장 | 새로고침 후 세트·모드·문항·답안 복원 |
| 가져오기/내보내기 | 왕복하면 진행이 그대로 |
| 퀵 | 전 세트에서 뽑고, 회차 목록·요약·타임라인에 남지 않음 |
| 퀵 — 오답 | 출처 세트별로 오답노트에 뜨고, 세트 오답 버킷(`reviewIds`)은 오염되지 않음 |
| 퀵 — 영속 | 채점 직후 새로고침해도 회차·퀵 오답이 남고, 24시간 뒤 사라짐 |
| 챕터 통계 | 같은 문항을 다시 풀어도, 세트 간 재수록 문항이어도 분모를 한 번만 셈 |
| 제품 스코프 | ISTQB↔CSTS를 오가도 상태·저장 키가 새지 않음 |
| 탭 간 | 두 탭에서 진행해도 나중 저장이 앞선 기록을 지우지 않음 |

## 반복해서 나온 결함 클래스

이 저장소에서 실제로 났던 유형이다. 앱 로직을 고칠 때 훑는다.

1. **쓰는 곳 없는 키를 읽는다** — 조회가 늘 비어 화면이 "없습니다"라고 거짓 안내. 키를 읽는 코드를 추가하면 쓰는 코드의 위치를 함께 적는다.
2. **영속화 트리거 누락** — `saveUiState` allowlist와 `useQuizStore.subscribe` 목록은 항상 같이 고친다.
3. **제품 스코프 누락** — `sessionScopeDefaults()`에 빠진 필드는 제품 전환 때 이전 값이 살아남아 상대 제품 키에 기록된다.
4. **키 조립 중복** — 답안·채점 키는 `answerKey.ts`의 `gradeKeyFor`·`answerKeyPrefix`·`answerKeyFor`로만 만든다.
5. **전멸형 로드** — 부분 실패를 허용할 곳(퀵의 전 세트 로드)은 `Promise.all`이 아니라 `allSettled`.
6. **같은 술어, 다른 범위** — 화면 카운터와 기록이 같은 판정 함수를 써도 세는 집합이 다르면 갈린다. 범위까지 같은지 교차 계약 검사로 고정하고(`quickStats.test.ts` '점수판 × 채점 범위'), '답함'은 `isAnsweredInMode` 하나로 그린다.
7. **동기 상태 + 비동기 목록** — 모드·세트는 즉시 바뀌고 문항은 나중에 온다. 목록 출처는 `data-list-mode|set|chapter`에 적고, 진입은 그 값으로 기다린다(`waitForList`).
8. **미룬 저장이 키를 나중에 읽는다** — 디바운스·타이머로 미룬 쓰기는 필요한 값을 전부 인자로 받는다. 키 함수에서 기본값을 없애 빠뜨리면 컴파일이 막히게 한다(`uiStorageKey(product)`).
9. **짝지어 지워야 하는 상태를 한 경로만 지운다** — 답안과 채점 표시처럼 함께 사는 값은 초기화 경로를 전부 세고 헬퍼 하나로 모은다(`dropQuickGraded`).
10. **키에 축이 하나 빠졌다** — 키 규약을 바꾸면 그 키를 쓰는 곳을 전수 조사한다(`reviewKeyFor`·`isReviewKeyOf`가 미니 시험과 세트 랜덤을 가르는 이유).
11. **레지스트리에 등록되지 않은 구성원** — 새 오버레이는 같은 커밋에 `useBackDismiss`(또는 `registerBackGuard`)를 넣는다. 빠지면 APK 뒤로가기에서만 드러난다.
12. **이름과 다른 동작** — 버튼이 약속한 일을 실제로 하는지 본다. 동작할 수 없는 컨트롤은 안내를 붙이지 말고 내린다.
