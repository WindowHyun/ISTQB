# 데이터 하네스

## 적용 범위

다음 변경에는 이 하네스를 사용합니다.

- `public/data/**/*.json`
- `www/data/**/*.json`
- 문제 ID, 제목, 메타데이터, 정답, 선택지, 해설, 그림, 표, 목록, block 구조
- 문제 데이터를 추출, 정규화, 검증, 보정하는 스크립트

## 목표

데이터 하네스는 문제 콘텐츠가 구조적으로 유효하고, 화면에 렌더링 가능하며, 내부 정합성을 유지한다는 것을 증명해야 합니다.

## 필수 점검

저장소 기본 검증을 실행합니다.

```bash
npm run verify
```

문제 데이터(`www/data/**`)를 수정했다면 원본 PDF 대조 게이트도 통과해야 합니다(CI `pdf-data` job과 동일).

```bash
python3 scripts/verify-pdf-data.py   # 정답 626문항 · 텍스트·밑줄 전수 대조 (pymupdf 필요)
#
# 텍스트 조각 수는 여기 적지 않는다 — 데이터가 늘면 함께 늘어나는데 강제하는 검사가 없어
# 조용히 어긋난다(실제로 2,489로 적혀 있었고 실측은 2,616이었다). **정본은 실행 출력이다**:
#   [1/3 텍스트] N조각 · 불일치 0 / [2/3 정답] 검사 626 / [3/3 밑줄] 검사 N · 미반영 0
# 문항 수(626)만 남긴다 — 계약 테스트(allsets.contract)가 강제하는 값이라 어긋날 수 없다.
```

이 명령은 문법 검사, 문제 검증, 콘텐츠 감사, 분류 마커 감사를 포함해야 합니다.

## 데이터 보정 도구 — 결과를 자동으로 채택하지 않는다

`scripts/fix-questions.js`(+`normalize-utils.js`)는 PDF에서 뜯어낸 문항을 보기 쉬운 모양으로
되돌립니다. **검토 도구이지 변환 파이프라인이 아닙니다.**

- 산출물은 원본 옆이 아니라 `reports/normalized/<원본경로>`에 같은 이름으로 나옵니다.
  `www/data`는 배포되는 자산 폴더라 그 옆에 파일을 두면 세 가지가 한꺼번에 깨집니다 —
  `sync-assets`가 `public`·`dist`로 복사해 번들·APK에 싣고, `validate-questions`가 그 폴더의
  `*.json`을 전부 읽어 같은 문항을 두 번 세며, `.gitignore`가 그 이름을 덮지 않아 실행할
  때마다 커밋 후보가 쌓입니다. `reports/`는 이미 무시되는 산출물 폴더입니다.
- 채택하려면 그 아래 파일을 같은 경로의 원본 위로 복사한 뒤 `npm run verify`로 확인합니다.

### ⚠ 보기 키 재부여

지문이나 한 덩어리 보기에서 보기를 뽑아낼 때, 새 보기에는 **나온 순서대로** `a`·`b`·`c`·`d`
키를 새로 매깁니다. 그런데 정답(`answer`)은 원본 키를 그대로 들고 있고 **둘을 이어 주는 것이
없습니다.**

- 원본 키가 달랐다면(`A`·`B`·`C` / `1`·`2`·`3`) 정답 키가 새 목록에 없어 검증에서 잡힙니다.
- **원본도 이미 `a`~`d`였다면 아무것도 잡지 못합니다.** 뽑아낸 순서가 원본과 다르면 정답이
  조용히 다른 보기를 가리키는데, 데이터는 멀쩡해 보이고 모든 검증을 통과합니다 —
  사용자만 맞는 답을 골랐는데 오답 처리를 당합니다.

그래서 **키를 다시 매겼으면 무조건 수동 검토로 올립니다**(`scripts/normalize-utils.test.ts`가
이 계약을 고정합니다). 검토자는 새 보기의 순서가 원본과 같은지, `answer`가 여전히 옳은 보기를
가리키는지를 눈으로 확인합니다. 검토 도구에서는 놓치는 쪽이 과하게 잡는 쪽보다 훨씬 비쌉니다.

## 확인할 내용

- JSON이 정상 파싱되는지 확인합니다.
- 문제 ID가 **스캔 전체에서** 중복되지 않는지 확인합니다. 종전에는 파일 단위라 세트 간 충돌을
  볼 수 없었는데, 재수록 그룹표(`build-duplicate-groups.js`)가 "같은 문제라도 세트마다 id가
  다르다"를 전제로 짜여 있어 그 전제가 깨지면 그룹이 잘못 묶입니다. 문항 **번호**는 반대로
  파일 안에서만 유일하면 됩니다(세트마다 1번부터 다시 셉니다).
- 필수 메타데이터가 있는지 확인합니다.
- 객관식 문제에 유효한 선택지가 있는지 확인합니다.
- 정답 키가 실제 선택지와 매칭되는지 확인합니다.
- 해설과 지문이 지원되는 block 구조를 사용하는지 확인합니다.
- 그림과 이미지 경로가 커밋된 실제 에셋을 가리키는지 확인합니다.
- 수동 줄바꿈, 표, 목록이 의도된 형식이며 렌더링 가능한지 확인합니다.
- 정본 `www/data`와 `public/data` 사본이 동기화되어 있는지 확인합니다(`npm run sync:assets`).

## 하네스를 보강해야 하는 경우

다음 결함이 발견되면 검증 규칙을 추가하거나 보강안을 제안합니다.

- 현재 검증이 허용하는 잘못된 block 타입
- 현재 검증이 탐지하지 못하는 누락 에셋 경로
- 중복되거나 불안정한 문제 ID 패턴
- 구조적으로는 유효하지만 의미적으로 잘못 매칭된 정답
- PDF 추출/정규화 과정에서 반복되는 결함
- **데이터는 유효한데 화면만 깨지는 경우** — 이 하네스의 사정권 밖입니다. 렌더러가 지문
  문자열을 바꾸는 결함 클래스는 `ui-render-harness.md`의 '렌더러가 데이터를 바꾼다'를 봅니다.
- **보정 도구가 만드는 새 위험** — 위 '보기 키 재부여'처럼, 도구가 조용히 뜻을 바꿀 수 있는
  자리는 검증 규칙이 아니라 **검토 강제**로 막습니다.

## 보고 체크리스트

최종 응답에는 다음을 포함합니다.

- 변경한 데이터 파일
- 검증 명령 결과
- 수동 검토가 필요한 콘텐츠 리스크
- `www/data` 동기화 필요 여부
