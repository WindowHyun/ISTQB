조치 — 저장소 키를 만드는 함수에서 기본값을 전부 제거해 제품을 필수 인자로 받게 했습니다. 빠뜨리면 컴파일이 막힙니다. flushPersist는 제품이 비어도 대기 중인 저장을 flush합니다.

R-1

렌더러가 정상 문장을 붙여 “참여할인력”으로 보여준다

HIGH

src/utils/parser.tsx · stripPdfNoise() — .replace(/할\s+인/g, "할인")

PDF 추출에서 갈라진 낱말을 되붙이는 규칙인데 조건이 없어, 할로 끝나는 관형형 + 인으로 시작하는 명사를 만나면 정상 문장을 붙입니다. 626문항 전수에서 6곳 발동, 그중 4곳이 오작동합니다.

ISTQB-B #18 리뷰에 참여할 인력 → 참여할인력 ❌ CSTS-2402 #38 진행할 인력과 조직 → 진행할인력과 ❌ CSTS-2402/2403/2404 #48 수행할 인적 자원 → 수행할인적 자원 ❌ ISTQB-D #20 같이 할 인 유형 → 할인 유형 ✅ 의도대로 ISTQB-EXTRA #22 높은 할 인을 → 할인을 ✅ 의도대로

저장소가 스스로 반대로 일하고 있습니다. scripts/normalize-utils.js에는 '리뷰에 참여할인력' → '리뷰에 참여할 인력' 하드코딩 치환이 있습니다. 데이터 쪽에서 일부러 복원해 둔 띄어쓰기를 렌더러가 다시 붙이고, 최종 승자는 렌더러입니다.

왜 게이트가 못 잡았나 — verify-pdf-data.py의 norm()이 비교 전에 re.sub(r"\s+", "", s)로 공백을 전부 제거합니다. 띄어쓰기 차이는 원리적으로 이 게이트의 검출 대상이 아닙니다.

제안 — /할\s+인(?=[을를])/로 좁히면 진짜 아티팩트 2건만 남고 오작동 4건이 사라집니다. 공백은 어차피 정규화되므로 PDF 게이트에 안전합니다.

저장소에 이미 해법이 둘 있습니다 — helpers.answerCurrent(제목의 ‘복수정답’ 표기를 보고 나머지를 고름)와 react-quick-ux.spec.ts:244의 결정적 quickDraw 시딩. 세 지점만 그 해법을 안 씁니다.

E-2

이름이 비슷한 검사가 다른 축을 재고 있었다

주의

e2e/react-study-ux.spec.ts · “랜덤 채점이 시험 오답 목록을 덮어쓰지 않는다(오답 모드 합집합)”

이름은 F-4와 겹치지만 검사하는 축이 다릅니다 — 시험 키 ↔ 랜덤 키는 원래 키가 달라 덮어쓰지 않습니다. F-4가 고친 것은 같은 랜덤 키를 공유하는 전체 랜덤 ↔ 챕터 미니이고, 이 테스트는 수정 전후 모두 통과합니다. 비슷한 이름의 검사가 있으면 “이미 덮여 있다”고 오판하기 쉬운 자리입니다.

다음에 할 일

비용 대비 효과 순
  1. R-1 — 유일하게 지금 사용자 화면에 보이는 결함이고, 정규식 한 줄로 닫힙니다.
  2. F-5 · E-1 — 세 스펙이 이미 있는 헬퍼를 쓰게 바꿉니다. 중복 구현이 아니라 중복 제거이고, CI의 E2E smoke 잡이 10번에 한 번씩 빨간불이 되는 것을 멈춥니다.
  3. R-3 · AN-1 — 둘 다 APK에서만 드러나 제보가 잘 들어오지 않는 자리입니다. 뒤로가기 가드는 기존 useBackDismiss 재사용, 시스템 바는 테마 변경 시 네이티브에 알리는 경로가 필요합니다.
  4. R-5 · R-6 — 도구를 한 번 쓰면 데이터·배포가 오염됩니다. 출력 경로를 reports/(이미 gitignore됨)로 옮기고 경고를 적습니다.
  5. CS-1 — 규칙을 지우거나, 주석의 잘못된 전제를 고칩니다. 남겨 두면 다음 사람이 되살립니다.
  6. R-2 · R-7 — 전부 잠복입니다. 검사를 붙여 두면 데이터가 바뀌는 시점에 잡힙니다.

이 점검이 보증하지 않는 것

실행하지 않은 스위트 — test:nf(비기능)·test:apk(WebView)는 단일 webServer를 공유해 react 스위트와 동시 실행이 불가했습니다. 영속화 계층을 고쳤으므로 배포 전 test:nf 한 번과 실기기 Safari 30초 확인을 권합니다.

실행 환경 제약 — verify-pdf-data.py는 원본 PDF와 pymupdf가 없어 생략했습니다(CI가 담당). E2E는 Playwright 1.61이 요구하는 chromium 빌드가 없어 미리 설치된 chromium을 지정한 임시 설정으로 돌렸습니다 — 스펙·프로젝트 정의는 저장소 것 그대로입니다.

정적 열람의 한계 — CSS는 규칙과 셀렉터를 읽고 죽은 규칙을 계량했을 뿐, 실제 렌더를 눈으로 확인하지는 않았습니다. 반응형·안전영역은 test:apk가 맞는 도구입니다.
